# 按量模型分时定价

## 状态

- 设计状态：Active
- 实现状态：Implemented locally
- 最后更新：2026-08-18
- 产品入口：渠道逐模型定价、分组逐模型价格覆盖、公开模型列表、登录用户可用模型

## 问题与目标

当前上游实现把 `peak_rate_enabled`、`peak_start`、`peak_end`、`peak_rate_multiplier` 放在 Group 上，并且只允许 `subscription_type=subscription` 的分组启用。该实现能对 token 请求叠加一个单窗口倍率，但不符合本 fork 的主要业务：站点以标准分组的按量扣费为主，分时价格属于模型销售价格，而不是订阅权益。

本功能把分时价格定义为“模型价格条目的时间维度”：

- 标准按量分组是主要使用场景，订阅类型不是准入条件。
- 一条逐模型价格可配置多个高峰或低谷窗口。
- 运行时规则跟随最终命中的价格来源，而不是固定读取 Group 的订阅字段。
- 用户看到的输入、输出、缓存写入和缓存读取价格，由真实计费所用的同一价格与倍率计算。
- 分时规则启用后，当前时段倍率就是该模型价格的最终 token 倍率，替代分组默认倍率、用户专属倍率和旧 `peak_rate_*`；关闭后原倍率链保持不变。

## 非目标

- 不做法定节假日、调休或工作日日历。
- 不按流式 token 的生成时间拆分一次请求。
- 不把用户销售价格规则复用于上游账号成本、调度权重或账号统计成本。
- 首版不改变按次图片、视频、音频、Web Search 或其他 per-request 价格。
- 不为每个时段保存一份重复的绝对价格；价格始终由基础价格和倍率派生。

## 价格归属与优先级

统一价格解析顺序保持不变：

```text
分组逐模型价格
  -> 渠道逐模型价格
  -> LiteLLM 内置价格
  -> fallback 价格
```

新规则存放在可配置的逐模型价格条目中。最终命中的 Group 或 Channel 价格条目同时提供基础价格和分时规则。若命中 Group 逐模型覆盖，则它连同自己的分时规则一起覆盖 Channel 价格；不同来源的价格和时段规则不拼接。

LiteLLM 和 fallback 没有管理员持久化的分时规则。需要为这类模型设置分时价格时，管理员应建立 Group 或 Channel 逐模型价格条目。

当 Group 或 Channel 条目只配置分时规则、没有重复填写基础 token 单价时，客户目录与真实结算必须共同使用 `BillingService` 的 `LiteLLM -> fallback` 基础价格链；不得出现页面无报价但后台仍按 fallback 扣费。

## 数据合同

`ChannelModelPricing` 增加可选的 `time_pricing`。该结构同时服务于渠道逐模型价格与 `groups.model_pricing` 中的分组逐模型覆盖：

```json
{
  "platform": "deepseek",
  "models": ["deepseek-chat", "deepseek-reasoner"],
  "billing_mode": "token",
  "input_price": 0.0000036,
  "output_price": 0.0000108,
  "cache_read_price": 0.00000012,
  "time_pricing": {
    "enabled": true,
    "timezone": "Asia/Shanghai",
    "default_label": "平时",
    "default_multiplier": 0.8,
    "rules": [
      {
        "label": "上午高峰",
        "start_time": "09:00",
        "end_time": "12:00",
        "multiplier": 2
      },
      {
        "label": "下午高峰",
        "start_time": "14:00",
        "end_time": "18:00",
        "multiplier": 2
      }
    ]
  }
}
```

合同约束：

- `time_pricing` 缺失或 `enabled=false` 表示不启用；`enabled=false` 只暂停规则，不删除已保存的时区、其余时段或显式规则，重新开启时可以继续编辑原配置。
- 仅 `billing_mode=token` 可以启用。
- `timezone` 必须是 Go `time.LoadLocation` 可识别的 IANA timezone。
- `default_label` 是未命中显式规则时展示给用户的类型名称，启用时必填，去除首尾空白后最多 32 个字符。
- `default_multiplier` 是未命中任何显式规则时使用的倍率，范围为 `[0, 100]`；旧数据缺失该字段时兼容为 `1`。
- 每条规则使用分钟精度 `HH:MM`。
- `start_time == end_time` 非法；首版不使用该写法表达全天。
- `start_time < end_time` 表示当天区间；`start_time > end_time` 表示跨午夜区间。
- 区间统一为左闭右开 `[start_time, end_time)`。
- 同一规则集在循环的 24 小时内不得重叠。
- 每条规则倍率范围为 `[0, 100]`；`0` 表示免费窗口。
- 每个价格条目最多 16 条显式规则。
- 每条显式规则的 `label` 是展示给用户的类型名称，启用时必填，去除首尾空白后最多 32 个字符；它不参与时间匹配或金额计算。
- 未被任何显式规则覆盖的时间使用 `default_multiplier`，称为“其余时段”，并展示 `default_label`。
- 类型名称和倍率相互独立：管理员可以把 `1.1x` 命名为“平时”，也可以把 `0.8x` 命名为“夜间优惠”；系统不得根据数值擅自改写名称。
- 显式规则可以为空；此时 `default_multiplier` 覆盖全天。

## 运行时语义

### 时段选择

定价解析器先解析最终模型价格，再在 `pricing_at` 时刻选择该价格条目的分时规则：

```text
分时定价启用：基础 token 价格 x 当前分时倍率 = 用户实际 token 价格
分时定价未启用：基础 token 价格 x 原用户有效分组倍率 = 用户实际 token 价格
```

这里的“替代”是完整替代：启用分时定价后，不再读取分组默认倍率、用户专属倍率或旧 Group peak 倍率参与该模型的 token 金额。未启用时，原合同仍是“用户专属倍率优先于分组默认倍率”，并继续兼容旧 Group peak。

渠道启用 `billing_model_source=response_model` 时，响应模型准入必须比较应用分时规则后的最终 `ActualCost`，而不是倍率前的 `TotalCost`。响应模型不得提高用户最终费用，也不得通过 `0x` 分时规则把原本应计费的请求归零。

### 请求边界

- 普通 HTTP 请求使用请求开始时刻，整次请求保持同一个分时倍率。
- OpenAI Images 的 token 计费和 cyber 失败用量记录同样沿用原请求开始时刻；异步落账不得在记录时重新取当前时间。
- 请求跨过价格切换点时不按 token 拆账。
- WebSocket 每个独立计费 turn 使用该 turn 的开始时刻重新选择规则。
- 时间选择使用规则中的 IANA timezone；响应和审计中的绝对时刻使用 UTC。

### 旧规则兼容

旧 Group `peak_rate_*` 暂不删除：

- 新模型分时规则存在并启用时，当前时段倍率直接成为最终 token 倍率，不再叠加分组默认、用户专属或旧 Group peak 倍率。
- 新模型分时规则不存在时，保留旧行为，避免既有安装实例升级后静默改变费用。
- 新管理端不再把旧规则作为主要配置入口。
- 后续删除旧字段必须单独经过数据使用情况核对和迁移窗口。

### 计费模式

首版分时倍率只应用于 token 模式，包括文本 token、缓存 token 和按 token 计价的图片 token。以下项目不应用：

- `per_request`
- 图片按张
- 视频按次
- 音频分钟、字符或小时价
- Web Search 按次
- Account Stats 自定义成本价格

## 管理端交互

分时定价位于复用的“模型定价条目”卡片内，不位于订阅配置区域。

token 价格卡片包含：

1. 分时定价开关。
2. 可搜索的 IANA 时区选择器，优先展示浏览器时区和常用时区，并允许保留或录入运行时列表之外的合法 IANA 标识。
3. 可编辑的“其余时段”类型名称和倍率。
4. 可排序的显式规则行：类型名称、开始、结束、倍率、删除。
5. “添加时段”按钮。
6. 每条规则的跨午夜和 `0x` 风险提示；`0x` 只描述金额结果，不能覆盖管理员配置的类型名称。

保存前浏览器提供即时错误，服务端执行同等或更严格的权威校验。重叠错误必须指出冲突的两条时间范围。`0x` 必须通过免费警告和 `$0.0000` 价格明确金额结果，但不得把管理员配置的类型名称改写成“免费”。

账号统计成本规则复用了模型价格表单结构，但不显示分时定价入口。

## 用户价格展示

`/model-plaza` 和 `/available-channels` 使用同一客户安全组件展示价格表：

| 时段 | 类型 | 输入 / 1M | 输出 / 1M | 缓存写入 / 1M | 缓存读取 / 1M |
| --- | --- | ---: | ---: | ---: | ---: |
| 其余时段 | 平时 `x0.8` | 基础模型价 `x0.8` | 基础模型价 `x0.8` | 基础模型价 `x0.8` 或 `—` | 基础模型价 `x0.8` 或 `—` |
| 09:00-12:00 | 上午高峰 `x2` | 基础模型价 `x2` | 基础模型价 `x2` | 基础模型价 `x2` | 基础模型价 `x2` |

展示约束：

- 明确展示 IANA timezone。
- 当前命中行同时使用文字/图标与样式高亮，不能只依赖颜色。
- 没有配置的价格显示 `—`；真实零价格显示 `$0.0000`。
- 分时规则启用时，公开页与登录页都只应用当前分时倍率；分时规则未启用时，用户专属倍率只影响登录用户自己的 `/available-channels`，公开 `/model-plaza` 使用公开标准分组倍率。
- 不暴露上游账号、渠道成本、利润阈值、路由拓扑或其他用户的专属倍率。

## API 投影

管理端 Group/Channel DTO 和客户安全的 available-channel pricing DTO 均可携带：

```json
{
  "time_pricing": {
    "enabled": true,
    "timezone": "Asia/Shanghai",
    "default_label": "平时",
    "default_multiplier": 0.8,
    "rules": []
  }
}
```

客户 API 返回 `default_label`、显式规则的 `label` 和基础模型价格；这些名称是管理员明确配置的客户文案，不包含内部备注。存在 Group 逐模型覆盖时，同时只为本次可见分组返回 `group_pricing[{group_id,pricing}]`，前端先选择最终价格条目再计算实际价格。实际价格由共享、纯函数式前端投影计算，服务端计费仍是唯一金额权威。该前端函数必须用固定时钟单测覆盖边界和跨午夜，且不得重新定义规则匹配语义或根据倍率推断类型名称。

`GET /v1/sub2api/billing` 是无模型参数的 Key 级倍率接口，无法准确表达模型级分时价格。本功能不把模型规则错误投影成 Key 全局倍率；该接口继续保留旧 group peak 兼容字段。

## 持久化与迁移

- `groups.model_pricing` 已是 JSONB，新字段随价格条目保存，不需要新增 Group 列。
- `channel_model_pricing` 新增 `time_pricing JSONB NOT NULL DEFAULT '{}'::jsonb`。
- Account Stats 的模型成本价格表不新增或消费该字段。
- Channel repository 的 list/create/update/replace/batch-load 必须完整往返该 JSON。
- `ChannelModelPricing.Clone()` 必须深拷贝规则切片，防止缓存对象被调用方修改。

## 审计

新请求在管理员可见的 usage `schedule_meta` 中保留：

- `pricing_at`
- 应用的分时倍率
- 实际展示的类型名称
- 分时时区
- 命中规则的 label/start/end/multiplier 快照

规则后续被编辑时，历史 usage 不回算。审计只记录实际命中的显式规则；命中“其余时段”时记录实际 `default_multiplier` 和空规则快照。

## 验收标准

### 配置与校验

- 标准分组中的 Group 模型价格可以启用两条以上规则。
- Channel 模型价格可以启用同一结构，保存并重新打开后无损往返。
- “其余时段”倍率可配置为 `[0,100]`，未配置显式规则时可作为全天倍率使用。
- 时区通过可搜索选择器完成，已有合法 IANA 标识不会因不在预置列表中而丢失。
- “其余时段”和显式规则都可以填写最多 32 个字符的类型名称，类型名称与倍率独立保存。
- 客户目录原样显示配置的类型名称，不根据倍率自动替换成高峰、低谷、平时或免费。
- 类型名称为空或超长时，浏览器和服务端都拒绝保存。
- `09:00-12:00` 与 `11:00-13:00` 被拒绝为重叠。
- `23:00-07:00` 合法并保持一条规则展示。
- 跨午夜规则与凌晨规则发生重叠时被拒绝。
- 非 token 价格启用规则时保存失败。

### 扣费

分组默认倍率 `1.2`、用户专属倍率 `0.8`、时段倍率 `2`、其余时段倍率 `0.5` 时，因为分时规则已启用，高峰最终 token 倍率为 `2`，其余时段为 `0.5`。分时规则关闭后才恢复用户专属 `0.8`（或无专属值时的分组默认 `1.2`）。
- `09:00-12:00 x2` 在 `09:00` 命中，在 `12:00` 不命中。
- `23:00-07:00 x0.5` 在 `23:30` 和 `06:30` 命中，在 `07:00` 不命中。
- Group 模型价格规则优先于 Channel 模型价格规则，二者不叠加。
- 未命中显式规则时使用 `default_multiplier`，旧 JSON 缺失该字段时仍使用 `1x`。
- 新模型规则存在时替代分组默认、用户专属和旧 Group peak；新规则不存在时旧请求金额保持不变。
- per-request 和图片按次价格不应用分时倍率。

### 展示

- 基础输入 `$3.60`、输出 `$10.80`、缓存读取 `$0.12` 在 `x2` 行分别显示 `$7.20`、`$21.60`、`$0.24`。
- 公开目录和登录目录使用同一时段表组件；分时启用时两者都直接展示“基础价 x 时段倍率”，不再隐藏叠加公开倍率或用户专属倍率。
- 基础输入价 `$1.00`、分组或用户倍率 `1.1`、其余时段倍率 `1.1` 时，当前输入价必须是 `$1.10`，不能显示或扣除 `$1.21`。客户目录直接展示最终价格，不额外暴露“当前有效倍率”或分组倍率标签；管理员配置与可展开时段表仍保留倍率用于规则解释。
- 当前行、时区、未配置价格与真实零价可区分。

### 回归

- 现有 token 上下文阶梯价格继续工作，分时倍率应用到最终命中的阶梯价格。
- API Key auth cache、Channel cache 和价格更新后的失效行为保持正确。
- 渠道定价顺序、模型映射覆盖、公开模型交付判断不因新增字段改变。
- 后端测试、前端单测、typecheck、lint 和 docs build 通过。
