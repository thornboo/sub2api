# 模型状态 V1：优先级探测链路

> 2026-09-07，用户批准实现。适用于 V1 站点自检；本页记录行为合同及验证结果。

## 目标与执行规则

管理员从模型状态卡片进入详情，能够同时回答：目前哪些账号可以探测、顺序是什么，以及最近一轮实际尝试过哪些账号、在哪一步失败或成功。

一次任务对应 `(group_id, model)`，不再对应单个账号。候选账号按账号管理的 `accounts.priority` 升序排列，数值越小越先探测；同优先级按账号 ID 升序打破平局。分组关联表中的优先级不覆盖此合同。仅支持该模型且满足当前资格的账号参与执行。

| 模型 | 示例账号支持范围 | 应执行的候选顺序 |
| --- | --- | --- |
| flash | A：flash，优先级 1；B：flash/pro，优先级 3；C：flash/pro/exp，优先级 2 | A → C → B |
| pro | 同上 | C → B；A 显示不支持该模型 |
| exp | 同上 | C |

同一轮串行执行。失败或单次超时后立即尝试下一候选，首个成功结束该轮，其余候选标记为因前序成功未探测。每次上游调用最多 30 秒，整轮最多 90 秒；总预算耗尽后剩余候选标记未探测，不伪造上游失败。相同目标由 runner 内互斥、数据库事务领取和未完成轮次唯一索引共同防止重叠，不同分组的同名模型独立记录。进程中断留下的轮次超过 120 秒（90 秒执行预算及 30 秒落库余量）后由下一次领取标记未完成并释放，不补造探测成功。

账号执行前再次检查资格，覆盖账号／模型冷却、配额、过载、到期和 Spark 母凭据等既有规则，保留 Antigravity overages 例外。失去资格只跳过，内部读取失败与真实上游失败区分。V1 原有的严格平台匹配边界仍保留，混合平台资格属于原问题 3 的后续工作。

## 状态含义

| 一轮的证据 | 对外状态 |
| --- | --- |
| 第一位实际尝试的合格账号成功 | operational |
| 实际发生失败，后续备用成功 | degraded，模型仍可用 |
| 全部实际尝试失败且没有成功 | failed |
| 当前无合格账号 | failed / no_available_account |
| 尚无完整新鲜轮次、执行未完成或证据不足 | unknown |

上游 429 不能当成成功终止切换。步骤已开始但因中断缺少完整结果时标记 `incomplete`，不混同于完全未尝试的 `not_attempted`。被排除或未尝试的备用账号不能被当成成功，也不因缺少本轮探测而自动拉低首选成功的状态。当前状态不能用无关账号旧成功拼接；历史指标继续优先读分组模型快照。固定 10 分钟新鲜窗口沿用当前行为，其与长探测间隔的冲突仍在原问题 4 中跟踪。

## 管理员详情与权限

新增只读 `GET /api/v1/admin/model-self-check/chain?group_id=...&model=...`，挂载既有管理员认证路由。

- 当前候选：账号 ID / 名称、平台、当前优先级、可参与顺序、资格与排除原因、账号上次实际探测结果和时间。
- 最近一轮：开始／结束、总耗时、最终状态、成功账号，以及每一步执行顺序、当时名称和优先级、结果、原因、HTTP 状态及耗时。
- 当前配置与历史执行记录分区显示；改账号优先级或名称不会改写过去一轮。
- 未执行备用账号展示其上次真实检测时间，不包装为本轮健康。
- 详情打开是读取记录，不发起新探测；页面加载、失败重试和切换卡片均不能触发模型请求。
- 普通用户不请求或渲染此接口；既有 `/api/v1/model-status` 和详情 DTO 不增加账号、优先级或内部错误字段。

名称使用“探测链路”。它反映站点自检的优先级切换，不能保证真实用户请求一定选择同一账号；会话粘性、并发、成本和请求特定条件仍可影响业务调度。

## 存储与升级

新增迁移 `237_model_self_check_probe_rounds.sql`，只增加 `model_self_check_probe_rounds` 表及目标／时间索引、未完成轮次唯一索引。`steps` 是经过白名单 DTO 序列化的 JSONB 数组，不保存凭据、地址或上游响应正文。轮次执行时写入，完成后不可更新；账号标识没有账号外键，避免删除账号破坏历史名称和优先级证据。

历史账号探测记录、Token 统计和脱敏状态快照保留，不清空、重算或补造旧链路。轮次保留期沿用自检快照保留设置，0 表示保留。升级后需要新后端应用迁移并执行真实新轮次，才会出现完整链路；本次实现不代替用户启动或重启服务。

## 验收与验证

验收覆盖模型支持过滤、优先级和平局、首选成功停止、失败后切换、全部失败、无资格、单次／整轮超时、执行中资格变化、同模型不同分组隔离、历史不可变、候选／已执行证据分离、管理员鉴权和普通用户脱敏。

本地验证使用合成账号、模拟传输和一次性测试数据库，不使用生产凭据或发起真实模型请求。

- 后端 `-tags=unit`：service、repository、handler、handler/admin、server/routes、migrations 六包全量通过；最终异常收尾及数据库互斥改动另做定向回归。
- 仓储 PostgreSQL 集成通过：迁移幂等、JSONB 往返、精确目标配对、历史不可更新、保留期、过期轮次接管；8 个并发领取者仅 1 个成功。
- runner 定向 `-race` 通过；Go vet 与后端编译通过。
- 前端链路 API、面板、页面权限／请求取消、国际化测试：4 个文件、20 项通过；类型检查、lint 和生产构建通过。
- 文档构建通过。构建存在已有的包体积等非阻断提示。

## 详情样式调整（2026-09-07）

根据管理员实际截图反馈，取消 Token 和探测链路区块的绿色背景／外框，改用中性分隔线。Token 改为一行汇总，候选数量和超时改为辅助信息行；当前候选与历史执行分别采用紧凑对齐行，优先级、平台不再堆叠胶囊标签。状态色只用于实际结果，候选排序编号保持中性。仅调整展示和说明文案，不改变探测、权限或数据口径。页面视觉由用户自行查看，不使用 Playwright。

## Review 后的边界修复（2026-09-07）

- 单账号超时从进度写入和资格复查结束后开始计时。进度写入受整轮上下文取消约束，准备期间预算耗尽时标记未探测，不调用上游、不写账号失败历史；最终收尾仍使用独立的有界上下文落库。
- 每次执行前使用重新读取的 `GroupIDs` 检查账号是否仍属于目标分组；已移出的账号跳过并标记 `group_removed`，不消耗该账号的探测请求。
- 管理员打开的详情链路随页面自动刷新静默更新，保留现有内容，并继续受关闭弹窗、切换模型和权限变化时的请求取消保护。
