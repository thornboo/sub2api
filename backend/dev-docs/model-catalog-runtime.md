# 模型目录运行指标

可用渠道和公开模型列表共用目录接口中的运行指标，不发起主动探测，不依赖模型状态页开关或 monitor-v2 聚合任务。两处页面都使用实际数据，不再在开发环境自动填充 mock。

## 统计范围

- 维度为 **分组 ID + 用户请求的模型 ID（大小写不敏感）**。同一分组内，`claude-fable-5`、`Claude-Fable-5` 和 `cLaude-faBlE-5` 的样本按小时合并计数及耗时，再计算成功率、延迟和吞吐；不同分组仍独立统计，不合并不同别名、标点或版本号。仅统计服务内部归一化匹配键，日志原文及目录显示名称保持不变。同一分组模型出现在多个渠道时复用同一份指标。
- 窗口为最近 24 小时，截止到最近一个整分钟，分为 24 个连续的一小时桶。桶随窗口滚动，不是本地时区的自然小时。
- 每个应用进程共享一分钟缓存，并合并并发刷新。数据库只返回聚合数据；接口只附加当前目录已经授权、发布的分组模型。
- 公开模型列表保留原有公开标准分组及 callable 模型策略；登录后的可用渠道仍显示管理员配置的模型。

## 成功率与样本

成功样本来自 `usage_logs`：保留成功落账记录，也保留零倍率但有 token、图片或视频用量证据的记录；排除全零失败占位记录、安全拦截记录和额外的 `web_search:` 工具账单。按 API Key + 计费请求 ID 去重。

失败样本来自 `ops_error_logs` 的客户可见终态记录。复用现有 Ops SLA 归因，只把平台或上游造成、`sla_impact=true` 的终态失败纳入模型成功率。排除 token 计数、已恢复的重试尝试、客户参数/权限/余额拒绝和客户端取消。历史记录沿用 `opssql` 的兼容归因；无法判定的 SLA 责任不作为确定失败。

普通 HTTP 的 `client_request_id` 由网关为每次请求生成，不读取客户端传入的同名请求头；`request_id` 可以来自客户端传入的 `X-Request-ID`。终态错误按 API Key + 网关生成的 `client_request_id` 去重，缺失时才依次回退到 `request_id`、错误记录 ID，并使用不同前缀隔离这三种标识。这样客户端复用 `X-Request-ID` 不会合并独立失败，同一请求的重复终态记录仍只保留最新一条。

普通 HTTP 用量记录的 `client:<id>`、`local:<id>` 分别与错误记录的 `client_request_id`、`request_id` 关联，且关联限定在同一个 API Key 内。已记录终态错误的请求即使产生了部分用量，也不能同时计为成功。客户端取消关联的部分用量也从成功集合中排除。

成功率为 `成功数 / (成功数 + 纳入统计的最终失败数)`。全窗数值由各桶的计数求和后计算，不平均各小时的成功率。请求量小于 20 时 API 保留样本较少状态，但卡片不显示“样本较少”或“暂无调用”提示；没有可判定样本时比率与延迟返回 `null`，卡片显示 `—`，不填 100% 或零延迟。吞吐在前端最多显示两位小数，计算与 API 精度保持不变。

## 延迟与吞吐

- Token 模型：平均有效流式 `first_token_ms`。该字段在部分协议中记录的是首个流事件，并不保证是第一个文本 token；沿用网关现有转发计时边界。
- 图片模型：成功样本的平均 `duration_ms`，标为生成延迟。
- 其他按次模型：成功样本的平均 `duration_ms`，标为响应延迟。
- 吞吐为有效流式样本的 `sum(output_tokens) × 1000 / sum(duration_ms - first_token_ms)`。只纳入输出 token 为正、首事件耗时为正、总耗时大于首事件耗时的成对样本。它是输出阶段估算速度，不是站点总 token 流量，也不包含输入或缓存 token。
- 缺少流式时间字段的非流式请求不会补入首字延迟或吞吐。图片等非 token 计费卡片不展示 token 吞吐。

## 账号状态

`schedulable_group_ids` 来自现有 `ModelDeliveryService` 的稳定账号路由：使用分组、模型映射、平台限制及账号 active/schedulable 配置。它不使用 24 小时流量、临时限流、并发负载或协议发布状态来判断账号是否存在。

- 字段存在但不包含当前分组：显示唯一的“暂无可用账号”提示。
- 字段缺省：元数据不可用，不误报没有账号。
- 状态与运行统计独立；有调度账号不等于请求必定成功。

## 数据边界

本功能复用已有用量和运营错误日志，未修改计费 ID、请求转发或调度规则，也未新增数据表。要展示成功率，现有运营错误采集必须启用；关闭时接口省略运行指标，保留价格和账号状态，避免把缺失的失败记录显示成 100% 成功。

历史日志保留期、曾经关闭或丢失的日志会限制统计完整性。零费用且没有任何用量证据的历史记录无法可靠区分成功与失败，因此不推测成功。部分 WebSocket turn、异步媒体任务使用上游或持久任务 ID，无法按普通 HTTP 的关联规则准确合并两张表；不使用时间相近等启发式匹配，也不改动这些 ID 的计费幂等语义。

统计查询失败不会隐藏已配置模型，也不会触发 mock 回退。不存在逐用户、逐卡片查询，或从页面触发上游调用的路径。
